# 共存虚拟盘后台优化与可靠性评估

## 本次行为

- 胡桃启动游戏页面后，应用生命周期内每分钟检查一次已选择的共存库。默认开启闲时优化和游戏运行期间优化，可分别关闭。
- 无游戏运行时，系统连续两分钟无键鼠输入才开始；游戏运行期间，允许开关开启即可开始。用户恢复操作、关闭选项或切换库后，在下一个文件边界暂停。退出应用会取消任务。
- 当前应用会话内成功处理后，同一库六小时内不再自动扫描；失败后十分钟再试。不会为后台维护自动挂载离线磁盘。
- 专用 Windows 后台模式线程降低 CPU、I/O 和内存调度优先级，不修改胡桃或游戏进程的优先级。后台哈希同步执行在该线程，每 MiB 检查取消；克隆每段检查取消。
- 游戏可继续运行。只对 StreamingAssets 下的 `.blk`、`.pck`、`.usm` 大文件去重，跳过未完成版本和正在写入、无法获得共享许可的文件；每次修改前重新计算双方 SHA-256。低优先级会减少争用，不能保证完全无帧率影响。
- 应用内安装、更新、修复会取消优化并等待其关闭文件句柄，包操作完成前保持暂停；转换、删除也会先取消优化。每个优化文件单独持有游戏路径读锁，有写操作时退出。外部启动器通过 Windows 文件共享规则协调。手动扫描和优化也使用低优先级线程。
- 优化只重新共享相同内容的 ReFS 数据块，不删除文件、不执行 VHDX 压缩，不保证立即降低宿主文件大小。
- 添加游戏可直接选择已有胡桃共存库的 `game.vhdx`，要求同目录保留 `virtual-disk.json` 和 `installations.json`。验证卷身份后挂载并选择完整版本；不会初始化任意外来镜像。已有版本库不依赖原游戏目录存在。

## 开启和关闭共存时的迁移

- 开启新共存库时，询问导入完成后是否清理原安装，默认保留。复用已有库不会触发原安装清理。
- 初次导入和恢复使用完整复制，包含截图、配置和缓存；不同版本之间的快照仍使用原有筛选规则。
- 副本复制、SHA-256 校验及安装信息检查全部成功后，才将共存版本标记为完整并允许清理原安装。清理时再次检查全部原文件和副本，再逐文件复核并删除。
- 清理中断不会回滚已提交的共存版本：当前游戏切到完整虚拟盘版本，未删除的原文件保留，显示清理未完成提示。不递归删除原目录，保留其空目录结构。清理前持久化 `OriginalCleanupPending`，重启后禁止自动切回可能只剩部分文件的原安装；旧目录元数据缺少此字段时按 false 读取。
- 关闭共存时，选择恢复当前版本到普通目录，或仅关闭。恢复会新建独立目录，不覆盖已有安装，虚拟盘版本保留；失败或取消时继续保留共存状态。
- 仅关闭时切回仍存在的原安装；若原安装已删除，则清空当前游戏选择，允许以后重新添加虚拟盘。成功恢复后将恢复目录记为新的普通安装路径。
- 本次仅实现以上迁移选项，未添加 VHDX 压缩或容量缩小操作。

## 元数据能提高什么可靠性

可以添加。建议分两层建设，第一层优先；目前仅增加迁移所需的兼容性字段 `OriginalCleanupPending`，以下完整性与冗余方案尚未实现。

| 元数据 | 作用 | 限制 / 成本 |
| --- | --- | --- |
| 描述文件、版本目录的 schema 版本、库 UUID、递增 generation、内容校验和 | 发现截断、错配及意外修改；拒绝使用不一致身份 | 校验和不能防止恶意重写，也不能恢复丢失的游戏数据 |
| 描述文件与版本目录的上一代副本，并在虚拟盘内部保存一份对应副本 | 在单份宿主目录元数据丢失时提供恢复依据 | 必须核对镜像、卷和版本 UUID；内部副本需先只读挂载才能访问，不应猜测身份后直接写入 |
| 原子提交日志：operation UUID、generation、目标版本、准备 / 完成状态 | 恢复导入、转换、删除中断；区分完整安装与半成品 | 当前已有 Pending 和临时文件原子替换基础；多文件提交仍需明确提交顺序和恢复协议 |
| 分版本文件清单：相对路径、大小、SHA-256、官方清单来源与版本 | 定位损坏文件，支持校验和定向重新下载 | 全盘初次哈希需要大量 I/O；时间戳、文件 ID、USN 只能帮助失效缓存，不能代替校验 |
| 分块校验和及恢复来源索引 | 对大型资源精确定位损坏块，匹配官方资源分块重下 | 要处理更新失效和清单清理；不能把共享物理块的另一个版本当作独立备份 |

建议先做“带版本与代数的元数据双副本 + 原子提交日志”，随后做可取消的完整性检查，使用官方清单或独立校验来源定位并重新下载损坏资源。恢复时让用户核对库身份、报告冲突；不要静默用旧目录覆盖新状态。

## 数据修复的边界

ReFS 块克隆共享物理数据，多个版本中同一块损坏可能同时影响多个版本。哈希元数据只能检测此问题。单个 VHDX / 单块宿主磁盘也不自动具备冗余修复能力。

若需要离线自修复，需要额外的独立备份或纠删码 / PAR2 等冗余数据，并明确预留空间、写入一致性、校验和恢复流程。建议作为可选功能，放在独立物理磁盘；同一 VHDX 内的校验数据仍受镜像损坏影响。ReFS integrity streams 可作为后续兼容性实验，但必须验证块克隆、游戏更新器与反作弊，不宜默认批量启用。

不应缓存物理 extent 地址作为持久真相：更新、重分配和重挂载后可能变化。优化仍应使用当前句柄、最新哈希与文件系统返回的块信息。
