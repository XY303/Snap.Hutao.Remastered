# 多服共存实验原型

本分支支持关联两份已有的官服默认和国际服默认客户端，共享内容一致的部分资源，并在启动时选择对应安装目录。它不会自动下载或生成另一份客户端。

## 使用限制与风险

- 仅支持同一台计算机、同一 NTFS 卷、互不嵌套的两个真实安装目录。目录及资源路径不能经过 Junction、目录符号链接或文件符号链接。
- 两份客户端必须先分别校验修复，配置与 ScriptVersion 均有效且版本一致。只接受 channel=1、sub_channel=0，不支持 bilibili、Epic 等其他渠道。
- 仅处理 `_Data/StreamingAssets` 下的 `.blk`、`.pck`、`.usm`。相对路径、长度和实际 SHA-256 均一致才创建硬链接；不共享整个目录、程序、配置、SDK 或 Persistent。
- 本地文件哈希一致不代表通过官方完整性校验，也不意味着该资源在未来版本一定可以安全共享。
- 硬链接不是备份，也不提供自动写时复制。外部程序写入任一共享文件可能同时破坏两份安装。
- 官方启动器更新、游戏内热更新、反作弊和第三方工具的兼容性尚未实测，可能出现无法预见的错误，包括校验失败、资源损坏、无法启动和重新下载。不得把本原型视为已经兼容这些工具。
- 不支持两服同时运行。进行任何关联、恢复或更新操作前，应关闭游戏、官方启动器和第三方工具。程序无法阻止其他程序在操作期间自行启动。

## 界面流程

“启动游戏”页面的“多服共存（实验性）”中，选择另一份已安装客户端。第一次对话框展示风险和限制；第二次独立对话框展示两边路径并再次确认风险。两个对话框均默认取消，任一步取消都不会创建共享链接。

关联后，选择官服默认或国际服默认并启动，会切换到关联目录；“根据账号自动选择服务器”也复用这个过程。关联目录不会再执行原地跨服转换。需改用其他渠道时，先恢复独立并解除关联。

“恢复独立并解除关联”会把两边仍共享的受管理资源复制为独立文件，再解除目录关联。恢复可能需要与共享资源总量相当的额外空间。失败或取消后应重试恢复，不能直接删除关联记录。

## 更新与故障恢复

程序内安装、更新、校验修复和预下载在开始包操作前，先在可取消、可重试的进度窗口内恢复当前安装的独立资源。更新空间预估包含解除共享的额外空间。目录关联会保留，但资源不再自动重新共享；两服更新到一致版本并分别校验后，可再次关联。

使用官方启动器或第三方工具修改、修复或更新前，必须先在本程序中恢复独立并解除关联。绕过本程序的更新不受上述保护。

两个安装根目录中的 `snap_hutao_server_coexistence.json` 是恢复记录。它在创建共享链接之前写入，并记录计划处理的路径；因此中断可能留下多余记录，但正常操作不会产生没有记录的共享链接。恢复时检查实际硬链接数量，避免重复复制已经独立的文件。准备中的临时文件使用记录中的 PairId 命名，可以在恢复时清理。

不要手动删除或编辑这些记录，也不要移动关联中的安装目录。外部删除记录、绕过程序改动资源或进程在文件替换瞬间异常退出后的完整客户端兼容性，仍需要进一步验证。

## 当前验证范围

自动化测试使用临时目录和模拟资源，验证真实 NTFS 硬链接、内容差异筛选、恢复后原地写入隔离、取消恢复、进程中断留下的临时文件恢复、关联记录校验、目录越界防护及 Junction 拒绝。

尚未对真实游戏、官方启动器更新、游戏内热更新、反作弊和第三方工具执行端到端兼容性验证。正式推广前应使用可恢复的测试安装验证上述场景，并测试磁盘不足、外部占用、不同版本更新和进程异常退出。
