# ReFS 虚拟磁盘多服版本库（实验性）

开启“虚拟磁盘多服共存”时，先显示兼容性风险确认，再让用户选择存放位置，最后确认源安装和目标位置。首次完整复制当前客户端。手动切换和普通启动均优先选择已有的匹配版本，缺少时才新建。重复切换同一区服不再生成额外副本。同区服、渠道和游戏版本的历史重复副本在启动版本列表中合并显示，实际数据仍保留。支持启动页面所有可选择的区服／渠道，包括 bilibili，不包括仅为兼容旧配置保留的方案。

关闭共存时切回版本库记录的原始安装，恢复原来的原地转换流程；不删除 VHDX 或已有版本。再次开启并选择同一父目录时可复用之前的版本库。历史版本通过列表选择。点击“选择此版本”会同步游戏路径及目标区服，并等待旧路径的刷新结束，避免启动时被旧区服选回。若开启“按账号自动选服”，启动时仍按该选项匹配账号区服。“删除版本”列表包含全部副本及未完成版本，可确认后永久删除指定版本及其截图、配置。当前选中的安装需先切换到其他版本或关闭共存后才能删除；删除不会自动缩小宿主 VHDX。删除前校验所有路径，拒绝符号链接、目录联接和版本目录内的额外挂载点，删除中断时保留未完成标记以阻止启动。

开启共存后，原“转换”入口显示为“增加共存区服”，缺少目标区服时增加独立安装，已有区服直接复用。完成后保留当前启动路径及区服；通过“启动版本”或按账号自动选服切换到新安装。关闭后显示原服务器转换入口。按账号自动选服开关继续独立保留。共存开关与风险提示位于单独卡片；“虚拟硬盘管理”展开后分为启动版本、空间占用与优化、删除共存版本三项，分别执行对应操作。

## 数据布局和转换

```text
用户选择的位置/HutaoGame-随机标识.hutao-vdisk/
  game.vhdx                         动态 ReFS 虚拟磁盘
  virtual-disk.json                 宿主侧卷身份描述
  installations.json               宿主侧独立版本清单
  volume/versions/版本 GUID/
    YuanShen.exe 或 GenshinImpact.exe
    各自独立的配置、SDK、资源和运行时文件
```

转换前取得独占游戏目录锁，检查游戏已停止，查询源和目标正式分支并确认与安装版本相同。先写入未完成清单，再将当前版本复制到新的 GUID 目录。同卷内至少 1 MiB 的大文件直接使用 ReFS 块克隆，其他文件独立复制。跨区服使用原来的官方 Sophon 转换代码，渠道 SDK 使用原来的下载／替换逻辑，最后写入目标配置和版本元数据。源安装和历史版本保留。

文件都是独立文件对象，不使用硬链接。ReFS 负责写时分离，更新或修复一个版本不会通过硬链接修改另一个。中断或失败的版本保留为未完成，禁止启动和普通包操作；可以在退出胡桃后仅清理该 GUID 目录，或从完整版本重新转换。

只允许操作应用自己新建的磁盘；已有磁盘不会被格式化。挂载核对保存的卷 GUID 和实际可访问的 ReFS，防止离线挂载目录被当成宿主普通目录写入。创建和重新挂载需管理员权限、Windows ReFS 和 Storage PowerShell 支持；不安装驱动，不修改安全设置，不回退硬链接。

## 手动空间优化

页面即时显示 VHDX 在宿主上的分配空间，不会在每次打开页面时自动读取全部游戏文件。“扫描优化比率”按文件大小分组，对可能重复的大文件进行 SHA256 校验，并读取实际数据块范围。估算根据所有版本的物理块并集计算，已经共享的块不会重复计入可优化空间。小于 1 MiB 的文件、只读／加密／压缩／稀疏文件不参与优化。

“空间优化（块克隆）”重新扫描，独占源和目标的写入访问，重新校验 SHA256，再使用 FSCTL_DUPLICATE_EXTENTS_TO_FILE 共享相同数据的完整簇。未对齐的尾部保持独立。取消时只影响共享程度，不改变文件字节。优化完成后重新统计。

显示游戏逻辑体积、游戏数据块占用、估算可释放大小及其占当前游戏数据块占用的比例。该比例不包含 ReFS 元数据、缓存或其他卷内文件。扫描期间外部程序的修改可能使估算变化，实际修改前仍会再次校验。

块克隆释放虚拟盘内部空间，**不会自动缩小宿主 VHDX**，也不是后台自动去重。扫描和校验需读取所有候选大文件，可能耗时较长。游戏、其他启动器与外部修改工具应关闭。

动态磁盘容量上限为初始游戏体积的三倍加 32 GiB，最少 64 GiB；首次宿主空间要求完整副本加 16 GiB。版本数不受双服限制，但磁盘容量和宿主实际剩余空间仍有限制；后续更新、写时分离和差异资源会增加占用。

## 兼容性与验证边界

保留两次风险确认和页面常驻警告。Windows 版本、ReFS、虚拟磁盘、游戏更新器及反作弊的组合可能不兼容，可能产生无法预见的错误。应备份重要文件，仅通过胡桃启动和管理，不要交给其他启动器改写、移动已挂载容器或同时运行多个客户端。

自动化测试使用临时假安装和真实临时 VHDX，验证多版本复制、物理块共享、优化估算、写入隔离、过期哈希拒绝、取消、卷重挂载和错误路径。本轮完整运行 286 项全部通过。默认普通测试为 284 项通过、两项 VHDX 集成测试跳过，设置 HUTAO_VHD_INTEGRATION=1 并使用管理员权限可运行完整测试。

没有迁移用户的真实游戏。本轮未验证真实游戏启动、在线转换、更新和反作弊兼容性。旧格式的恢复代码继续保留，但新入口不再创建旧式双服关联。方案评估见 [存储后端评估](game-storage-backends-evaluation.md)。
